# Local workers (added 2026-11-03)

Routine typing goes to the gateway worker, which is Qwen3.8-Flash-Next on the Mac Studio, on live trial since 2026-11-21, with DeepSeek V4-Flash kept there as the fallback (the one line to go back is in `.gateway.toml`; Claude does not switch models on its own) (the `qwen-gateway` MCP tools, a historical name; config in `.gateway.toml`, which is local-only and never committed) or to cloud DeepSeek (`/pass-to-deepseek`). Claude writes the spec and reviews the diff.
The rules are the ones in `~/Developer/beezer/CLAUDE.md` ("Qwen Gateway — operating rules"); this is what differs here.

## Who gets what
- **Studio worker** (free, runs on the Mac Studio, about 35 s plus 45 s per 60 KB of listed files): up to about six files with a pattern to copy. A test in
  `src/__tests__`, a pure helper in `src/lib`, a copy or string change, a CSS tweak in one component. Since
  2026-11-04 it edits files with SEARCH/REPLACE blocks instead of rewriting them, so a small, well-specified
  change in `src/components/mobile/MobileEditor.tsx` (67 KB) or `src/components/timeline/TimelineDock.tsx`
  (42 KB) is fine to give it; what still rules a file out is the list below, not its size. When the gate fails,
  the retry automatically gets the files the errors name, and a failed task is undone by the gateway.
  Since 2026-11-27 the gateway runs all three gate commands before a retry (the retry sees every error), gives
  one free retry to a reply with no edit in it, and does not resend a task whose reply was cut off (split it
  instead). `cd ~/qwen-gateway && .venv/bin/python stats.py --since <date>` tallies passes and causes. A spec
  pastes any type the worker must match but cannot be shown (for example from `src/lib/ffmpeg`) and lists one
  similar file to copy.
- **DeepSeek** (`run.sh`): routine work bigger than two files, or that needs reading around the code. Its ask mode
  (`~/.claude/skills/pass-to-deepseek/ask.sh ~/Desktop/Projects/reelflowWeb "<question>"`, read-only) answers
  "where is X / how does Y work" so Claude does not read source to write a spec.
- **Claude or cloud DeepSeek, never the Studio worker:** `src/lib/mobile` (WebCodecs export, colour, the GPU compositor: Safari
  behaviour learned on the phone, not in any model's training), `src/lib/gl`, `src/lib/export`, `src/lib/color`,
  `src/lib/ffmpeg`, the `e2e/` scripts, anything under `src/app`, and anything that must be checked on the iPhone.

## What this repo expects (put it in every spec)
- Tests live in `src/__tests__/<name>.test.ts`, use `import { describe, expect, it } from "vitest"`, import code
  through the `@/` alias (= `src/`), and run in the node environment (no DOM, no window).
- The gate is `npm run lint`, `npm run typecheck`, `npm test`, in that order (434 tests, about 15 s together).
  Only lint errors fail it (warnings pass). eslint ignores `public/` (copied ffmpeg and MediaPipe bundles)
  since 2026-11-03; before that a clean tree had 19 errors from those bundles. Every spec says "no new lint errors in
  the files you touch", and Claude runs `npx eslint <those files>` in review.
- Never list `.env*`, `node_modules`, `out/`, or the copied ffmpeg files under `public/` for the worker.
- This is Next.js 16 (see AGENTS.md) built as a static export: no server routes, no server actions.

# Desktop app (added 2026-11-23)

`desktop/` is an Electron shell that shows the built site (`out/`) in a window; the plan and what has been checked are in `docs/DESKTOP_PLAN.md`. `npm run desktop` builds and opens it, `npm run desktop:open` opens it without rebuilding.
- **Never change** the address `app://nocap` (`desktop/lib/appUrl.mjs`) or the app name "NoCap Edit" (`desktop/main.mjs`). Projects live in IndexedDB under that address, inside `~/Library/Application Support/NoCap Edit`; changing either makes every saved project disappear.
- `scripts/build-app.sh` runs the gate, builds, and installs "NoCap Edit.app" in /Applications (`--no-open` to skip opening). The app holds only `desktop/` and `out/`; projects are outside it, so reinstalling keeps them.
- `NOCAP_DATA_DIR=<folder>` points the app at another data folder. Use it for every test run so tests never touch the real projects.
- `desktop/main.mjs` and `desktop/preload.cjs` are Claude's (address, headers, security settings). Pure helpers in `desktop/lib/` with tests in `src/__tests__/` (imported by relative path, since `@/` only covers `src/`) can go to the Studio worker.
- In the app, exports run in the real ffmpeg program: `src/lib/ffmpeg/nativeFfmpeg.ts` stands in for ffmpeg.wasm and `desktop/ffmpegHost.mjs` runs the commands in a sandboxed temporary folder. Any failure falls back to the built-in engine, so the website's behaviour is the floor. Both files and `desktop/lib/ffmpegArgs.mjs` (the path and command checks) are Claude's; a change to the checks needs its tests in `src/__tests__/desktopFfmpegArgs.test.ts` updated in the same commit.
- Reels can use the Mac Studio's model in the app: the page calls `app://nocap/studio/v1/...` and `desktop/studioProxy.mjs` forwards the two allowed calls (list models, chat) with the key added. Where the Studio is, which model, and which file holds the key come from `~/.config/nocap-edit/studio.json`, which is outside the repo on purpose (the repo is public); without that file the choice does not appear. The model name there should match `.gateway.toml`, since the Studio takes about 40 s to swap models.
- The page gets no Node access. Anything it needs from the shell is added to the fixed list in `desktop/preload.cjs`.
- Android emulator (desktop app only): `desktop/phoneHost.mjs` runs `adb` to send an export to the phone, stream its screen (`screenrecord`, decoded in `src/components/phone/PhonePanel.tsx`) and walk Instagram through the Reel steps. The buttons live in the Instagram tool (`src/components/phone/InstagramPanel.tsx`), which a finished export opens. Like the ffmpeg host it is Claude's; pure helpers are in `desktop/lib/phone.mjs`. Instagram's screens are found by their resource ids and labels, so an Instagram update can break a step. Rules since 2026-11-26 (posting safety): the app only ever talks to an emulator, never a plugged-in phone (`firstDevice`); everything that drives Instagram goes through one gate (`desktop/lib/oneAtATime.mjs`), one run at a time, and Stop is checked again right before each tap that posts or changes the profile; a run returns `problems` for things asked for that did not happen, and the windows then do not count down to Share (`src/lib/phone/afterRun.ts`); each run in the Story and Post / Reel windows has its own cancel flag, so a closed run can never share. The Instagram panel offers a video only while it matches the open project (`src/lib/phone/exportFits.ts`: never another project's, never one made before an edit); with none, its buttons make it themselves with the default export settings, in memory, no save window (`exportForPhone.ts`), and `rendering` in the phone store stops two exports at once. The Story window's "Music from Instagram" box (song and artist, since 2026-11-26) exists because Instagram silences a well-known song that is baked into the uploaded video (a Story with "Timber" in its MP4 posted silent): `runStory` turns the video's own sound off, then `pickSong` in `desktop/phoneHost.mjs` searches Instagram's music list and picks the song only when exactly one row is that title by that artist (`findTrack` / `sameTrack` in `desktop/lib/phone.mjs`) and the player bar names the same song; anything else is a `problem`, so nothing is shared by itself. When the video is the open project's, it has a music track, the song boxes are empty and mute is off, the window warns above Go and in the countdown that it may post silent (`src/lib/phone/bakedMusic.ts`). The Story window's "Style it" button turns its "Text on the picture" words into an ordinary editor title (whole video, at Top/Middle/Bottom, `src/lib/phone/storyTitle.ts`) and opens the Text tool; the styled words are burned into the video, so Instagram's own text menus are not automated for styling. With DeepSeek set up, "Style it" also asks it for a look (`desktop/lib/styleAi.mjs` builds the ask and accepts only fonts and colours the editor has; `src/lib/phone/aiStyle.ts` applies it, the card in the Text tool offers Try another / Back to plain / Keep); the words and one frame of the video are sent to DeepSeek, only on that click. The card also has a "Words on the video" box (one undo step; Try another asks about the words as they are now), and a Text tool opened by "Style it" shows "Back to Instagram" at the top until the Instagram tool is opened again (`src/lib/phone/storyReturn.ts`). **Testing never taps Share**: it is a real account. To test the countdown, replace the `phone:*` handlers with fakes from Playwright's main process. The phone can only type plain keyboard characters (`input text` crashes on anything else). When the emulator is off, the Instagram tool and the phone panel show a Start button (`src/components/phone/EmulatorStart.tsx`, `phone:launch`): it starts the virtual phone that ran last (remembered in `emulator.json` in the data folder), using the emulator program whose SDK holds that phone's system image (there are two SDKs on this Mac), and the emulator keeps running when the app quits. To test it without touching the emulator that is open, point `NOCAP_ADB` at a script that hides it. The Story window's "Gemini picks the cover" switch (off by default) runs after the Story is added to the Highlight: `src/lib/phone/highlightCover.ts` grabs frames, Gemini picks one (`caption:cover`), and `phone:highlightCover` puts it on the Highlight through Edit cover → the phone's photos; it only saves when the edit screen names that Highlight and the first photo is minutes old. It changes a public profile, so testing it for real needs the user's yes. Android will not read a screen that keeps moving, and Instagram's feed and bubbles do, so the Highlight, cover and Home steps turn the emulator's animations off and put them back (`withStillScreen` in `desktop/phoneHost.mjs`; the user agreed to this for the emulator, never a real phone). When Gemini is busy (429, 5xx, no answer), `desktop/captionAi.mjs` sends the same request, caption polish too, to DeepSeek if `~/.config/nocap-edit/deepseek.json` (outside the repo) names a key file; without it the cover step falls back to Gemini's lighter model.
- Export folder (desktop app only): the Export panel can name one folder, kept in `export-folder.json` in the data folder; with it set, exports (video, subtitles, GIF, timeline) are written there with no save window and nothing is overwritten. `desktop/exportFolderHost.mjs` (Claude's) takes a file name only, never a path, and the folder comes only from the Mac's folder window; names are checked in `desktop/lib/exportFolder.mjs`; the page side is `src/lib/utils/exportFolder.ts`. The website downloads as before.
- "AI polish" for captions uses Gemini (`desktop/captionAi.mjs`). `~/.config/nocap-edit/gemini.json` (outside the repo) names the key file and the model; the button appears only when the key file has a key.
